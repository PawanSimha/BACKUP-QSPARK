To insert data into an Oracle database using Oracle APEX, you have several standard approaches depending on whether you are working in the development environment or building an end-user application.
The highlight in your image displays the SQL Workshop side menu bar (specifically pointing to the SQL Commands or Object Browser menu section).

Method 1: Using SQL Workshop (For Developers / Manual Testing)

If you want to manually insert rows into a table while designing your database:
1. Look at your sidebar image: Click the SQL Workshop icon (represented by the cylinder/database icon highlighted in your image).
2. Select SQL Commands.
3. Write a standard SQL INSERT INTO statement:sql
INSERT INTO employees (employee_id, first_name, last_name, email)
VALUES (employees_seq.NEXTVAL, 'John', 'Doe', 'john.doe@email.com');
Use code with caution.
4. Click the Run button in the top right corner.

Method 2: Creating a Form Page (For End-Users / Applications)

If you are developing an app and want users to input data via a web page:
1. Navigate to your App Builder and select your application.
2. Click Create Page.
3. Select Form from the page options.
4. Set the Source Type to Local Database and choose the target Table Name.
5. Oracle APEX will automatically generate the input page items (e.g., :P2_FIRST_NAME) and a Create/Submit button.
6. Automatic Processing: APEX automatically creates a page process of type Form - Automatic Row Processing (DML). When the user hits submit, APEX handles the INSERT query in the background without you needing to write raw SQL code.

Method 3: Custom PL/SQL Process (For Complex Logic)

If you need to perform validation or complex operations before inserting data from an application form:
1. Go to the Page Designer of your form page.
2. In the left panel (Processing tab), right-click Processing and choose Create Process.
3. Set the type to Execute Code (PL/SQL).
4. Write your custom code referencing the form page items as bind variables:sql
BEGIN
    INSERT INTO employees (first_name, last_name, email)
    VALUES (:P2_FIRST_NAME, :P2_LAST_NAME, :P2_EMAIL);
END;
Use code with caution.
5. Under the process attributes, set the When Button Pressed condition to your SUBMIT or CREATE button.

Method 4: Data Workshop (For Bulk Uploads)

If you need to import data from external spreadsheets or documents:
1. Click the SQL Workshop dropdown tab in the top navigation bar.
2. Select Utilities and click Data Workshop.
3. Choose Load Data.
4. You can drag and drop an XLSX, CSV, JSON, or XML file, or simply copy-paste raw text to populate an existing table or generate a brand new one.

Yes, creating 7 separate Excel files (or 7 sheets within one workbook) is the cleanest approach because Oracle APEX's Data Workshop imports data one table at a time.
However, you don't necessarily have to manage 7 separate files on your computer. You can choose whichever method below is easiest for you:

Option A: The 1-Workbook Method (Recommended for Organization)

Keep all your data in a single Excel workbook, but split it across 7 different tabs/sheets (e.g., Tab 1 for Employees, Tab 2 for Departments, etc.).
• How to load it: When you drag and drop this single Excel file into APEX, a dropdown menu will appear allowing you to select which sheet you want to load.
• You will run the import process 7 times, picking a different tab and a different target table each time.

Option B: The 7-File Method

Save each table's data as its own independent .xlsx or .csv file.
• How to load it: Drag, configure, and load file #1. Once finished, click "Load Data" again and repeat the process for files 2 through 7.

⚠️ Critical Rule before you start: The "Parent-Child" Order

Because you are loading 7 different tables, they likely have relationships (Foreign Keys). You must import them in the correct sequential order, or Oracle will give you an Integrity Constraint / Parent Key Not Found error.
• Always upload Parent tables first: Upload lookup/master tables that don't depend on anything else (e.g., Departments, Regions, Roles).
• Upload Child tables last: Upload tables that reference the parent tables (e.g., Employees, because an employee requires a Department_ID to exist first).

The appearance of the QSPARK_BOOKINGS_ERR$ table means that the data load failed because some rows in your CSV did not match the rules of your database table. Oracle automatically created this error table to log the rejected rows.

How to find out what went wrong:

1. Go to SQL Workshop > SQL Commands.
2. Run this query to see the exact error message for each failed row:sql
SELECT ora_err_mesg$, ora_err_tag$, a.* FROM QSPARK_BOOKINGS_ERR$ a;
Use code with caution.
3. Look at the ora_err_mesg$ column in the results. It will tell you the exact cause.

Common reasons for this error:

• Parent Key Not Found (Integrity Constraint): The bookings table might require an ID (like a CUSTOMER_ID or FLIGHT_ID) that belongs to another table you haven't uploaded yet. If so, you need to upload those Parent tables first.
• Data Type Mismatch: A text value in your CSV is trying to insert into a numeric or date column in the database.
• String Too Large: One of the text columns in your Excel file has more characters than the database column size allows (e.g., trying to put a 50-character string into a VARCHAR2(20) column).
